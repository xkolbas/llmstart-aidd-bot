# ADR 0001. Анализ фотографий из Telegram через OpenRouter

**Статус** — принято для итерации 9. **Дата** — 2026-11-20.

## Контекст

Бот анализирует фото еды и содержимого холодильника. Ответ должен учитывать подпись к фото, цели и ограничения из истории диалога. Текстовый режим уже использует `aiogram`, `AsyncOpenAI` и Chat Completions. Бот работает через polling в Railway. [Техническое видение](../vision.md), [план итераций](../tasklist.md).

Telegram передаёт в `message.photo` несколько размеров одного снимка. Бот скачивает нужный размер по `file_id`, например через `Bot.download` в `BytesIO`. Ссылка на скачивание файла из Bot API содержит токен бота. Её нельзя передавать провайдеру или записывать в логи. [Telegram Bot API — Message](https://core.telegram.org/bots/api#message), [Telegram Bot API — getFile](https://core.telegram.org/bots/api#getfile), [aiogram — Download file](https://docs.aiogram.dev/en/latest/api/download_file.html).

## Рассмотренные подходы

| Подход | Когда подходит | Компромисс для проекта |
|---|---|---|
| Один мультимодальный запрос с base64 data URL | Пользователь присылает непубличный файл, нужен ответ с учётом текста и изображения | Бот скачивает файл в память и отправляет его в `image_url.url`. Base64 увеличивает размер передаваемых данных примерно на треть. |
| Один мультимодальный запрос с HTTPS-ссылкой | Изображение уже доступно по ссылке, которую можно передать провайдеру | Запрос меньше. Для приватного Telegram-фото понадобятся отдельная публикация файла, например по временной подписанной ссылке, и управление сроком его жизни. |
| Анализ в два этапа | Нужен отдельный результат распознавания для повторного использования или проверок | OCR, модель распознавания объектов или мультимодальная LLM сначала извлекает признаки, затем текстовая LLM формирует ответ. OCR помогает читать этикетки, но не описывает блюдо. Два этапа добавляют задержку и могут потерять детали, которые первая модель не передала. |

Оба варианта прямой передачи поддерживаются OpenRouter. Для Chat Completions используется часть `image_url`, для Responses API — `input_image`. Responses API решает ту же задачу, но для текущего бота потребовал бы отдельного формата запросов и ответов. [OpenRouter — Chat Completions Vision Guide](https://openrouter.ai/blog/tutorials/send-image-to-llm/), [OpenRouter — Image Inputs](https://openrouter.ai/docs/guides/overview/multimodal/image-understanding).

## Решение

Отправлять одно фото с подписью и текстовой историей **одним мультимодальным запросом к OpenRouter Chat Completions**. Использовать отдельный заменяемый клиент изображений, настроенный через `OPENROUTER_IMAGE_MODEL`. Так сохраняются существующий SDK и схема диалога, а для загрузки фото достаточно Telegram Bot API и памяти процесса.

1. Telegram-обработчик выбирает самый подробный вариант фото, который укладывается в лимит размера для выбранного маршрута и бюджет памяти. Скачивает его асинхронно с ограничением размера. При превышении лимита или неподдерживаемом формате бот предлагает прислать меньший снимок или описать продукты текстом.
2. Сервис диалога передаёт клиенту изображения байты фото, подпись, историю и инструкции из `prompts/system.txt` и `prompts/image.txt`. Клиент формирует новое сообщение пользователя с текстом перед частью `image_url` и помещает байты в `image_url.url` как `data:<mime>;base64,<data>`. MIME-тип соответствует фактическому формату файла. Преобразование в формат OpenRouter остаётся внутри клиента.
3. Модель возвращает текст. Для еды она описывает видимое и обозначает неопределённость состава и порции. Для холодильника предлагает блюдо из различимых продуктов с учётом целей и ограничений. При нехватке данных задаёт уточняющий вопрос.
4. После успешного ответа в историю попадают подпись или пометка «Фото» и ответ. При сбое скачивания, запроса или пустом ответе история сохраняется без изменений. Исходное изображение и base64 остаются в памяти на время обработки, без записи в файлы или логи бота.

## Последствия и проверка

- На каждое принятое фото приходится один запрос бота к модели. Качество зависит от читаемости снимка и способности модели различать продукты. Модель и маршрут выбираются по поддержке изображений на входе, текста на выходе и base64, затем проверяются на фото еды и холодильника. [OpenRouter — модели и входные форматы](https://openrouter.ai/docs/guides/overview/models).
- Следующий текстовый ответ опирается на сохранённое описание и уточнения. Если нужно снова рассмотреть снимок, пользователь отправляет его повторно. Локальное отсутствие копий фото не определяет условия хранения у провайдера. [OpenRouter — Provider Logging](https://openrouter.ai/docs/guides/privacy/provider-logging).
- Автотесты с заглушками проверяют формирование `image_url`, передачу подписи и истории, сохранение только текста и поведение при ошибках. Ручная проверка в Telegram охватывает фото еды, фото холодильника и неразборчивый снимок. Конкретная модель и лимит размера подтверждаются при реализации.
