## Итерации

Требования и критерии качества: [техническое видение](vision.md). Каждая итерация оставляет работающего бота и добавляет новый функционал. После проверки результата дождись согласования пользователя перед следующей итерацией.

### 1. Первый запуск

- [ ] Подготовить проект и настройки; запустить бота локально с приветствием по `/start` и краткой инструкцией запуска.

**Проверка:** бот запускается по инструкции и отвечает на `/start`; отсутствие обязательных настроек вызывает понятную ошибку.

### 2. Ответы LLM

- [ ] Добавить ответы на текстовые сообщения через OpenRouter с ролью из системного промпта.

**Проверка:** отправить несколько вопросов в Telegram и получить ответы, соответствующие заданной роли.

### 3. Диалог с историей

- [ ] Добавить отдельную историю пользователей, вытеснение старых сообщений, `/clear` и последовательную обработку сообщений одного пользователя.

**Проверка:** бот учитывает контекст, разделяет диалоги пользователей и соблюдает лимит истории; `/start` сохраняет контекст, `/clear` и перезапуск очищают его. Быстрые сообщения и `/clear` обрабатываются по порядку.

### 4. Устойчивость и удобство

- [ ] Добавить обработку ошибок и пустых ответов LLM, длинных ответов, неизвестных команд и нетекстовых сообщений; настроить логирование.

**Проверка:** длинный ответ приходит полностью и по порядку; команды и вложения получают подсказки. При сбое LLM история сохраняется, следующий запрос работает; логи не содержат секретов и диалогов.

### 5. Запуск в Docker

- [ ] Добавить запуск и проверки через Docker, завершить набор Make-команд и инструкцию; проверить готовность MVP.

**Проверка:** бот работает по инструкции обоими способами запуска; согласованные команды доступны, автоматические проверки проходят, ручные сценарии и критерии готовности из видения проверены.

Для каждой итерации добавляй автоматические тесты нового поведения и выполняй доступные проверки качества. Автотесты используют заглушки внешних сервисов; ручные проверки выполняются с реальным ботом.
